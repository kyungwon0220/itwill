## 261016fri
### [Control File](261007.md#control-file) 이관
- Control 파일은, 운영중 이관 불가
1. 이관 前 [초기 파라미터 파일](InitializationParameterFileAndParameter.md#initial-parameter-file) Check
   ```SQL
   SHOW PARAMETER SPFILE;
   ```
2. ' control_files ' Parameter ( Static Parameter ) 수정
   ```SQL
   ALTER SYSTEM SET control_files='/home/oracle/Documents/insadata/control01.ctl' SCOPE=SPFILE;

   
   SELECT NAME FROM v$controlfile;
   ```
   - [Text Parameter File](InitializationParameterFileAndParameter.md#text-parameter-file) 경우, DB Down 後 편집기로 직접 수정 필요
3. DB 정상 종료 ( shutdown immediate; )
4. OS 內 물리적 File 이동
   ```CMD
   mv -v /u01/app/oracle/oradata/ORA19C/control01.ctl /home/oracle/Documents/
   mv -v /u01/app/oracle/oradata/ORA19C/redo01.log /home/oracle/Documents/
   mv -v /u01/app/oracle/oradata/ORA19C/redo02.log /home/oracle/Documents/
   ```
5. ```
   startup mount

   
   SELECT INSTANCE_NAME, STATUS FROM v$instance;
   ```
   > ' STATUS ' == ' MOUNTED ' == mount 시점까지 DB Open
6. Control File 內 Redo Log File 경로 정보 수정
   ```SQL
   ALTER DATABASE RENAME FILE '/u01/app/oracle/oradata/ORA19C/redo01.log' TO '/home/oracle/Documents/redo01.log';
   ALTER DATABASE RENAME FILE '/u01/app/oracle/oradata/ORA19C/redo02.log' TO '/home/oracle/Documents/redo02.log';


   SELECT MEMBER FROM v$logfile;
   ```
7. DB Open ( ALTER DATABASE OPEN; )

### Undo
- 8i Version 까지는, ' 롤백 ' 이라는 공간 관리였었고, 9i Version 부터 ' Undo ' 신규 용어 ( Oracle Auto 관리 )
  - ```SQL
    SHOW PARAMETER undo_management; /* VALUE AUTO == Oracle Auto 관리 */
    ```
    > 수동 관리로 변경시, 이점이 전혀 없기에 Auto 관리 고정 권장
- DML 작업시, 이전값 저장 공간
  - Transaction 끝나기 전까지, 이전값 보존 필수
  - Transaction 끝난 後 Undo Tablespace 內 여유 공간이 있다면, 유지 가능
    - ```SQL
      show parameter undo_retention;
      ```
      > ' VALUE ' == 초만큼 Transaction 이전값 유지 ( Undo Tablespace 內 여유 공간 있을시 )
- Instance Failure 발생시, Transaction 복구에 필요
- DB 운영중, 하나의 Undo 스페이스만 사용
- ```SQL
  CREATE UNDO TABLESPACE undo1 DATAFILE '/u01/app/oracle/oradata/ORA19C/undo01.dbf' SIZE 10M AUTOEXTEND ON;
  ALTER SYSTEM SET UNDO_TABLESPACE = undo1 SCOPE = BOTH; /* undo1 Tablespace 사용 지정 */
  SHOW PARAMETER undo_tablespace;
  ```
  > Undo Tablespace 생성 예제 코드

  |NAME|TYPE|VALUE|
  :---|:---|:---|
  undo_tablespace|string|UNDOTBS1|
- ```SQL
  SELECT n.usn, n.name, s.extents, s.rssize, s.xacts, s.status
  FROM v$rollname n, v$rollstat s
  WHERE n.usn = s.usn;
  ```
  |USN|NAME|EXTENTS|RESIZE|XACTS|STATUS|
  ---:|:---|---:|---:|---:|:---|
  0|SYSTEM|7|450560|0|ONLINE|
  1|SYSSMU1 1607784644$|5|3268608|0|ONLINE|
  2|SYSSMU2 3197760948$|5|3268608|0|ONLINE|
  3|SYSSMU3 2165878102$|7|5365760|0|ONLINE|
  . . .|. . .|. . .|. . .|. . .|. . .|
  - ' USN ' == Undo Segment ID
  - ' NAME ' = ' SYSTEM ' == Dictionary 테이블에 대한 변경 작업시 사용되는 Undo
  - ' EXTENTS ' == Undo Segment 內 Extent 수 ( Oracle Auto 관리 )
  - ' RSSIZE ' == Undo Segment 크기
  - ' XACTS ' == 진행중인 Transaction 수
    - 단, System Undo 경우, Transaction 수가 존재해도 ' 0 ' 표기된다
  - ' STATUS ' == DB Open 時 ' ONLINE ' ( Oracle Auto )
    - ```SQL
      ALTER SYSTEM SET undo_tablespace = undotbs1 SCOPE=BOTH; /* 사용하는 Undo File 변경 */
      ```
      - 기존의 Undo Segment == ' OFFLINE ' 처리
      - Transaction 진행중에, Undo File 변경 時 ' STATUS ' == ' PENDING OFFLINE '
        - ' STATUS ' == ' PENDING OFFLINE ' 존재시, Undo Tablespace 삭제 불가
- ```SQL
  SELECT segment_id,segment_name, owner, tablespace_name, status
  FROM dba_rollback_segs;
  ```
  > Undo Segment 정보 조회 예제 코드

  |SEGMENT_ID|GEGMENT_NAME|OWNER|TABLESPACE_NAME|STATUS|
  ---:|:---|:---|:---|:---|
  0|SYSTEM|SYS|SYSTEM|ONLINE|
  1|_SYSSMU1_1261223759$|PUBLIC|UNDOTBS1|ONLINE|
  2|_SYSSMU2_27624015$|PUBLIC|UNDOTBS1|NEEDS RECOVERY|
  . . .|. . .|. . .|. . .|. . .|
  - Undo Tablespace 생성시, Undo Segment 관리는 오라클이 Auto ( Segment 자동 생성 )
  - ' STATUS ' == ' NEEDS RECOVERY ' == 삭제되지 않으므로, 수동으로 Offline 처리 필요
    - 1. ```SQL
         SELECT segment_name || ',' FROM dba_rollback_segs WHERE STATUS = 'NEEDS RECOVERY';

#### Flashback
- Flashback Query
  ```SQL
  select current_scn, scn_to_timestamp(current_scn) from v$database;
  --4574979 17-NOV-26 07.17.29.000000000 AM


  update hr.employees set salary = 5555 where employee_id = 200;
  commit;


  select salary
  from hr.employees
  as of timestamp to_timestamp('2026-11-17 07:17:00', 'yyyy-mm-dd hh24:mi:ss')
  where employee_id = 200;
  --4840

  select versions_xid, salary
  from hr.employees
  as of scn 4574979
  where employee_id = 200;
  --4840
  ```
  > Transaction 종료 後 이전값 조회 예제 코드
- Flashback Version Query
  ```SQL
  select versions_xid, versions_operation, department_id, salary
  from hr.employees
  versions between timestamp to_timestamp('2026-11-17 07:17:00', 'yyyy-mm-dd hh24:mi:ss') and to_timestamp('2026-11-17 07:24:00', 'yyyy-mm-dd hh24:mi:ss')
  where employee_id = 200;

  select versions_xid, versions_operation, department_id, salary
  from hr.employees
  versions between scn 4574979 and maxvalue
  where employee_id = 200;
  ```
  |VERSIONS_XID|SALARY|
  ---|---:|
  0D0007007C010000|5555|
  0D0007007C010000|4840|
- Flashback Transaction Query
  - ```SQL
    alter database add supplemental log data;

    select supplemental_log_data_min from v$database;
    ```
    > ' versions_xid ' Recovery 時 활성화 필수
  - 수행된 Transaction (DML) 검색 가능
  - ' select any transaction ' System 권한 필요
  - ```SQL
    --update hr.employees set department_id = 50 where employee_id = 200;
    --update hr.employees set salary = 2597 where employee_id = 200;
    --delete from hr.employees where employee_id=200;
    --COMMIT;
    --alter system archive log current;


    select versions_xid, versions_operation, department_id, salary
    from hr.employees
    versions between scn minvalue and maxvalue
    where employee_id = 200; /* Flashback Version Query 조회 */
    --10000400DE010000	D	50	2597 /* 마지막에 수행된 Commit */
    --0D001400DE010000	U	50	2597
    --13001F00F0010000	U	50	2598
    --11001A006D010000	U	50	2599
    --		               50	2600


    select operation, undo_sql from flashback_transaction_query where xid='10000400DE010000'; /* 해당 Transaction 조회 */


    declare
        trans_arr xid_array := xid_array();
    begin
        trans_arr.extend;
        trans_arr(1) := hextoraw('10000400DE010000'); /* 마지막 Commit */

        dbms_flashback.transaction_backout(
            numtxns => 1,
            xids => trans_arr,
            options => dbms_flashback.cascade /* 종속된 트랜잭션까지, 역순으로 수행 (해당 Transaction, Archive File 필요) */
            );
    end;
    /

    COMMIT;
    ```
- Flashback Table
  - DB 운영중 Flashback Table Undo Data 사용하여, 특정 시점으로 복구
  - 통계 정보, Dictionary Table 불가
  - Flashback 대상 Table 구조가 바뀌었거나, 재구성시 불가 ( DDL 아닌, DML Flashback 가능 )
  - Flashback 수행하며 Redo, Undo 발생
  - Flashback 권한 필수
    ```SQL
    grant flashback on hr.employees to james; /* Object 권한 */
    
    grant flashback any table to james; /* System 권한 */
    ```
  - Row ( 행 ) 이동 활성화 필수
    - ```SQL
      alter table hr.employees disable row movement;
      alter table hr.employees enable row movement;


      select row_movement from dba_tables where owner = 'HR' and table_name = 'EMPLOYEES';
      ```
      > Row ( 행 ) 이동 활성화 예제 코드
  ```SQL
  flashback table hr.employees to timestamp to_timestamp('2026-11-17 07:17:00', 'yyyy-mm-dd hh24:mi:ss');
  ```
- Flashback Database
  - Archive 모드에서만 가능
  - RVWR(Recovery Writer) Background 프로세스가, Flashbackup Database Log, Redo 정보를 이용하여 DB 되감기 ( Control File 복원 및 재생성된 경우, Tablespace 삭제된 경우, Data File Level 재구성 경우 불가 )
    - Flashbackup Database Log == 1차적으로, Shared Pool 內 Cache 공간에 쌓이
      - ```SQL
        select * from v$sgastat where name like '%flashback%';
        ```
      - ' v$flash_recovery_area_usage ' 內 ' FLASHBACK LOG '
  - ```SQL
    alter system set db_flashback_retention_target = 2880 scope = both;

    
    show parameter db_flashback_retention_target
    ```
    > Flashback Database 가능 시간 설정 및 조회 예제 코드
  - ```SQL
    alter database flashback off;
    alter database flashback on;


    select flashback_on from v$database;

    ! ps -ef | grep rvwr | grep -v grep
    ```
  ```SQL
  create restore point before_hr_trunc;

  drop restore point befor_hr_trunc;
  
  select * from v$restore_point;
  ```
  > 복원 지점 생성, 삭제 및 조회 예제 코드
  ```SQL
  startup mount;

  
  flashback database to restore point before_hr_trunc;

  flashback database to timestamp to_timestamp('2026-11-17 08:15:00', 'yyyy-mm-dd hh24:mi:ss');

  flashback database to scn 4574979;


  alter database open read only;
  shutdown immediate;
  startup mount;
  alter database open resetlogs;
  ```
  - ```SQL
    select * from v$restore_point;
    ```
    > 복원 가능한 최전 시점 조회
