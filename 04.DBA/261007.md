### Control File <a id="control-file"></a>
- DB 구성 정보를 가진 File ( 작은 Binary ( 이진 형식 ) File )
- DB 현재 상태 정보 소유
- [mount](#startup-mount) 시점에서 필요, DB Open 이후 운영에도 필요
- 손실시 복구 필수 ( 다중화 권장 )
  - ```SQL
    ALTER DATABASE BACKUP CONTROLFILE TO TRACE AS '/home/oracle/control.sql';
    ```
    > Backup Control File 이용한 Trace File 생성 ( 차후, 백업 진도에서 배울 예정 )
  - Control File 다중화 권장
    - 1. [초기 파라미터 파일](InitializationParameterFileAndParameter.md#initial-parameter-file) 수정
      - ```SQL
        ALTER SYSTEM SET control_files = '/u01/app/oracle/oradata/ORA19C/control01.ctl', '/u01/app/oracle/fast_recovery_area/ORA19C/control02.ctl', '/u01/app/oracle/oradata/ORA19C/control03.ctl' SCOPE=SPFILE;
        ```
        > Control File 삼중화 예제 코드 ( Server Parameter File ( spfile ) 기반으로 DB 열려있는 경우 )
    - 2. DB 정상적인 종료
    - 3. ' control03.ctl ' 실제 파일 생성 ( DB 운영중 Copy 금지 )
      - Control File 줄이는 작업시 ( 예를들어, 삼중화에서 이중화 ), 불필요한 Control File 물리적 삭제 필요 ( 차후, 혼동 방지를 위해서 즉시 삭제 권장 )
      - ```cmd
        cp /u01/app/oracle/oradata/ORA19C/control01.ctl /u01/app/oracle/oradata/ORA19C/control03.ctl
        ```
        > 기존 ' control01.ctl ' 파일을 복사하여, ' control03.ctl ' File 생성
    - 4. DB 시작
- ```SQL
  SHOW PARAMETER control_files
  ```
  > Control File 실제 위치 정보 조회 예제 코드

  |NAME|TYPE|VALUE|
  |:---|:---|:---|
  contorl_files|string|/u01/app/oracle/oradata/ORA19C/control01.ctl, /u01/app/oracle/fast_recovery_area/ORA19C/control02.ctl
  > 동일한 파일을, 이중화로 저장
- DB 名, 식별자, 생성 시각, Data File, Redo Log File, 현재 사용중인 Redo Log File Sequence Number, Check Point, SCN, 백업 등의 정보 소유
  - ```SQL
    SHOW parameter db_name


    --SELECT * FROM v$parameter;


    --SELECT * FROM v$database; /* ' CHECKPOINT_CHANGE ' == 가장 최근 Check Point 발생 시점의 SCN Number */
    --SELECT * FROM v$datafile;
    --SELECT * FROM v$tempfile;
    --SELECT * FROM v$log;
    --SELECT * FROM v$logfile;
    ```
    > Control 파일이 가진 정보들

    |NAME|TYPE|VALUE|
    |:---|:---|:---|
    db_name|string|ora19c|

### shutdown
- startup 역순
- DB Buffer Cache, Redo Log Buffer 내용을 디스크에 기록 ( ' shutdown abort ' 종료시만은 제외 )
- DATA 파일, Redo Log 파일, [Control File](#control-file) 해제
- Background Process, SGA 메모리 ( Instance ) 해지
- DB 정상 종료 後 DB 재시작시, Instance Recovery 불필요 ( ' shutdown abort ' 종료시만은 Instance Recovery 필요 )
```sql
shutdown immediate
```
> ' shutdown ' == ' shutdown normal ' Default
```
Database closed. /* DATA 파일, Redo Log 파일 Close*/
Database dismounted. /* Control File Close*/
ORACLE instance shut down. /* Instance 해지 */
```

</br></br></br>
#### (1/4) shutdown normal
- DB 종료 기본값 모드
- 새연결 ( 새로운 Session 생성 ) 불가하나, sysdba 새접속만은 가능
- 오라클 서버가 모든 사용자들의 연결이 끊기기까지 대기 後 종료 ( 기존 DB 접속자들은, 계속 이용 가능 )
</br></br></br>
#### (2/4) shutdown transactional
- 새연결 ( 새로운 Session 생성 ) 불가하나, sysdba 새접속만은 가능
- Transaction 수행중인 Session 존재시, 모든 Transaction 끝나기까지 대기 後 종료 ( 새로운 트랜잭션 작업 시도시, 수행 불가 ERR 및 DB 접속 종료 처리 )
</br></br></br>
#### (3/4) shutdown immediate
- 새연결 ( 새로운 Session 생성 ) 불가하나, sysdba 새접속만은 가능
- Oracle 서버가, 연결된 모든 Session Kill ( PMON Background 프로세스가, 진행중인 Transaction 모두 ROLLBACK 처리 )
</br></br></br>
#### (4/4) shutdown abort
- 새연결 ( 새로운 Session 생성 ) 불가
- DB Buffer Cache, Redo Log Buffer 내용을 디스크에 기록하지 않고 종료
- DATA 파일, Redo Log File, [Control File](#control-file) 불안전 해제
  - 트랜잭션에 대해 COMMIT 및 ROLLBACK 못한 정보들이, 기록되지 않고 불안전 종료
- Background Process, SGA 메모리 ( Instance ) 불안전 해지
- DB 비정상 종료로서, DB 재시작시 SMON Background 프로세스가 open 시점에서 Instance Recovery
</br></br></br>
#### startup force
- shutdown abort + startup
  - 비정상 종료후 재시작 ( 재부팅 개념 )
  - Instance Recovery 필요
