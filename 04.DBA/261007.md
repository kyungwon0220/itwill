### startup
```SQL
SYS@ora19c> startup
```
```
ORACLE instance started. /* nomount == Instance 시작 */

Total System Global Area 1241513488 bytes
Fixed Size 8896016 bytes
Variable Size 318767104 bytes
Database Buffers 905969664 bytes
Redo Buffers 7880704 bytes
Database mounted. /* mount == Control 파일 열기 */
Database opened.
```
> ' startup ' 뒤에 옵션을 명시하지 않는다면, ' startup open read write ' 기본값으로 수행
- ' select name, open_mode from v$database; ' 실행하여 확인시, ' READ WRITE '
</br></br></br>
```SQL
startup pfile=/home/oracle/initora19c.ora
```
> 특정 위치에 존재하는, 초기 파라미터 파일로 DB Open 가능
</br></br></br>
```SQL
startup open read only
```
> READ ONLY 모드로 Open

</br></br></br>
#### (1/3) nomount
- Instance 시작
  - SGA(System Global Area) 영역, Background Process 생성
    - [초기 파라미터 파일](#initial-parameter-file) 참조하여 SGA(System Global Area) 영역 생성 ( 초기 파라미터 파일이 없을시, ' init<SID>.ora ' 파일을 찾고, 이도 없을시 startup ERR )
  - [alert_\<SID\>.log, trace 파일](#trace-file-path) 열기
- DB 생성, [Control 파일](#control-file) 재생성, 백업 및 복구 경우 == 의도적으로 nomount 단계에서 작업 필요 ( 차후 백업 진도에서 배울 예정 )
  - ```SQL
    SYS@ora19c> startup nomount
    ```
    ```
    ORACLE instance started.

    Total System Global Area 1241513488 bytes
    Fixed Size 8896016 bytes
    Variable Size 318767104 bytes
    Database Buffers 905969664 bytes
    Redo Buffers 7880704 bytes
    ```
    > nomount 단계까지만 startup
    ```SQL
    select instance_name, status from v$instance;
    ```
    > nomount 단계까지만 startup 결과 확인 예제 코드

    |INSTANCE_NAME|STATUS|
    |:---|:---|
    ora19c|STARTED|

    </br></br></br>
    - ```SQL
      alter database mount;
      ```
      ```

      ```
      > nomount 단계에서, 다음 mount 단계로
      ```SQL
      select instance_name, status from v$instance;
      ```
      > nomount 단계까지만 startup 결과 확인 예제 코드
      
      |INSTANCE_NAME|STATUS|
      |:---|:---|
      ora19c|MOUNTED|
      
      </br></br></br>
      - ```SQL

        ```

        ```
        > mount 단계에서, 다음 open 단계로

        |INSTANCE_NAME|STATUS|

#### (2/3) mount
- [초기 파라미터 파일](#initial-parameter-file) 내용 上 [Control 파일](#control-file) 위치를 파악하여, 이를 Open
- 데이터 이관 작업, NOARCHIVELOG 모드를 ARCHIVELOG 모드로 변경 작업, RMAN 이용한 CLOSE BACKUP 수행, 복구 작업시 == 의도적으로 mount 단계에서 작업 필요 ( 차후 백업 진도에서 배울 예정 )
</br></br></br>


#### (3/3) open
- DATA 파일, REDO LOG 파일 Open
- DB 비정상 종료 되었을 경우, SMON Background 프로세스가 Instance Recovery

### shutdown
- startup 역순
- DB Buffer Cache, Redo 로드 Buffer 내용을 디스크에 기록 ( ' shutdown abort ' 종료시만은 제외 )
- DATA 파일, REDO LOG 파일, [Control 파일](#control-file) 해제
- Background Process, SGA 메모리 ( Instance ) 해지
- DB 정상 종료 後 DB 재시작시, Instance Recovery 불필요 ( ' shutdown abort ' 종료시만은 Instance Recovery 필요 )
```sql
SYS@ora19c> shutdown immediate
```
```
Database closed. /* DATA FILE, REDO LOG FILE Close*/
Database dismounted. /* Control 파일 Close*/
ORACLE instance shut down. /* Instance 해지 */
```
> ' shutdown ' 뒤에 옵션을 명시하지 않는다면, ' shutdown normal ' 기본값으로 수행
</br></br></br>
#### (1/4) shutdown normal
- DB 종료 기본값 모드
- 새연결 ( 새로운 Session 생성 ) 불가하나, sysdba 새접속만은 가능
- 오라클 서버가 모든 사용자들의 연결이 끊기기까지 대기 後 종료 ( 기존 DB 접속자들은, 계속 이용 가능 )
</br></br></br>
#### (2/4) shutdown transactional
- 새연결 ( 새로운 Session 생성 ) 불가하나, sysdba 새접속만은 가능
- 트랜잭션 수행중인 Session 존재시, DB 종료하지 않고 대기 ( 사용자가 새로운 트랜잭션 작업 시도시, 수행 불가 ERR 및 DB 접속 종료 처리 )
- 모든 트랜잭션 종료시, DB 종료
</br></br></br>
#### (3/4) shutdown immediate
- 새연결 ( 새로운 Session 생성 ) 불가하나, sysdba 새접속만은 가능
- 오라클 서버가, 현재 연결된 모든 Session Kill ( PMON Background 프로세스가, 진행중이던 트랜잭션 모두 Rollback 처리 )
</br></br></br>
#### (4/4) shutdown abort
- 새연결 ( 새로운 Session 생성 ) 불가
- DATA 파일, REDO LOG 파일, [Control 파일](#control-file) 해제 ( 불안전 해제 )
  - 트랜잭션에 대해서 COMMIT 및 ROLLBACK 못한 정보들이 기록되지 않고 불안전 종료
- Background Process, SGA 메모리 ( Instance ) 해지 ( 불안전 해지 )
- DB 비정상 종료로서 DB 재시작시, open 시점에서 Instance Recovery
