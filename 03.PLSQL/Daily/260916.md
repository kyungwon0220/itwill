### 변수
- 변수명은 문자로 시작해야 한다 ( 문자, 숫자, 특수문자 ( _, #, $ ) 포함 가능 )
- 변수명의 길이는 30자 이하로 가능
- 변수명으로, 예약어는 사용 불가
  - ' SELECT * FROM v$reserved_words WHERE reserved = 'Y'; ' 실행 결과 == 사용 불가
- 변수 선언시 NOT NULL, CONSTANT ( 상수 ) 경우, 초기값 (기본값) 설정 (할당) 필수
  - ```SQL
    DECLARE
      name VARCHAR2(30); /* ' name ' == 디폴트 값인 NULL */
      job VARCHAR2(50) NOT NULL := 'Oracle DBA'; /* NOT NULL 존재시, 기본값 할당 필수 */
      day CONSTANT DATE DEFAULT SYSDATE; /* CONSTANT ( 상수 ) 선언시, 기본값 할당 필수 */
    BEGIN
    END;
    /
    ```
    - SQL DEVELOPER 프로그램 上 VARCHAR2 타입은 ' (20) ' 같이, 사이즈 미지정시 ERR

### 서버 프로세스 (Server Process)
![](../../SQL/Daily/mdIMG/260910ServerProcess.jpg)
> https://docs.oracle.com/en/database/oracle/oracle-database/19/cncpt/sql.html#GUID-1B95E60C-99C5-446D-9C6B-5D16EFE59ACF:~:text=the%20general%20stages%3A-,Figure%208%2D3%20Stages%20of%20SQL%20Processing,-Description%20of%20%22Figure
1. User Process, SQL 문장을 던진다
2. Server Process, CURSOR 메모리 할당받고
3. User Process 던져준 SQL 문장을 받아서, 이미지상의 ' Parsing ' 작업
- Syntax Check : 문법 체크
- Semantic Check : 의미 분석 체크 ( 오브젝트가 테이블이라면, 테이블 컬럼 체크 )
  - ```SQL
    SELECT *
    FROM SYS.USER$ /* Oracle 내부 데이터 딕셔너리 테이블 ( 직접 INSERT / UPDATE / DELETE / 구조 변경은 하지 않는 것이 원칙 ) */
    WHERE USERNAME = 'HR' /* ' HR ' 유저가 존재하는지 체크 */


    SELECT *
    FROM SYS.OBJ$ /* 내부적으로, 객체 체크시 활용 */
    WHERE OWNER = 'HR' AND OBJECT_NAME = 'EMPLOYEES'; /* ' HR ' 소유한, 'EMPLOYEES ' 객체 정보 조회 */


    SELECT *
    FROM DBA_TABLES /* Oracle 내부 데이터 딕셔너리 테이블 ( 객체 타입이 테이블일 경우, 테이블 스페이스 체크 ) */
    WHERE OWNER = 'HR' AND TABLE_NAME = 'EMPLOYEES'; /* ' HR ' 소유한 테이블 정보 조회 */


    SELECT *
    FROM DBA_TAB_COLUMNS
    WHERE OWNER = 'HR' AND TABLE_NAME = 'EMPLOYEES'; /* 컬럼 체크 */
    ```

### Shared Pool
![](../../SQL/Daily/mdIMG/260910SharedPool.jpg)
- Data dictionary Cache : Semantic Check 시도할 때마다, 디스크 I/O 발생을 줄이기 위해서 딕셔너리 정보를 메모리에 올려놓은 공간 ( 동일한 SQL 문장이 Shared Pool 메모리 안에, 라이브러리를 캐시 했는지 조회(있으면 쉐어링, 없으면 Hard Parsing) )
  - ' SELECT SQL_ID, SQL_TEXT, PARSE_CALLS, LOADS, EXECUTIONS, PLAN_HASH_VALUE, HASH_VALUE
FROM V$SQL ' 결과 == Shared Pool 內 Library Cache 內 SQL 문장
    - 결과상, ' PARSE_CALLS ' == Library Cache 요청한 횟수 ( ' EXCUTIONS ' 같이 증가 )
    - 결과상, ' EXCUTIONS ' == 실행 횟수 ( ' PARSE_CALLS ' 같이 증가 )
    - 결과상, ' LOADS ' == Library Cache 요청 했으나, 없을시 HARD PARSING 발생하며 증가하는 횟수 ( 실행 계획 생성 )
    - 결과상, ' PLAN_HASH_VALUE ' == 실행 계획 고유값 ( 이가 같다는 뜻은, 실행 계획이 같다는 의미 )
